# HorizonOS

Open source ос, в стиле windows 98.

## Что уже есть

- Шаг 1: рабочий стол, панель задач, «Пуск» с меню, часы, курсор из `.cur`, клавиатура и мышь.
- Шаг 2: GDT/TSS, IDT, синий экран при ошибках, куча (`alloc`), LAPIC + IOAPIC,
  клавиатура/мышь/часы по прерываниям, процессор спит в `hlt` вместо опроса.
- Шаг 3: диск A: — перечисление PCI, драйвер AHCI (чтение), FAT32 только на
  чтение. На рабочем столе временная строка с числом файлов в корне диска A:,
  уйдёт при появлении нормального рабочего стола со значками.
- Иконка на кнопке «Пуск» — твой логотип (`assets/icons/start.ico`), фон
  сделан прозрачным.
- Шаг 4: настоящий шрифт Terminus вместо временного X11; первое модальное
  окно «PC Manager» (Shutdown / Reboot / Sleep mode-заглушка) поверх
  затемнённого интерфейса; перед выключением/перезагрузкой — чёрный экран
  с сообщением, как в Windows 98.
- Шаг 5: звук. Драйвер AC97 (только воспроизведение), поддержка WAV
  (16 бит/стерео/48000 Гц). При загрузке рабочего стола играет
  `STARTUP.WAV`, при настоящем выключении — `SHUTDOWN.WAV` (при
  перезагрузке звука нет, так и задумано).
- Шаг 5.1: загрузка теперь в три этапа — картинка загрузки (пока диск,
  файловая система и звук готовятся) → голый рабочий стол с курсором
  «ожидание» и стартовым звуком в фоне → полный интерфейс с обычным
  курсором. Звук больше не блокирует — играет через DMA по-настоящему в
  фоне, а не «блокирующе фоном» как раньше.

## Установка

    sudo apt install qemu-system-x86 ovmf xorriso git build-essential dosfstools mtools
    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # если нет Rust

## Запуск

    make run

Первый раз скачает Limine (ветка v9.x-binary), крейт `linked_list_allocator`
и соберёт тестовый диск A: (`disk.img`, FAT32, 64 МБ, с файлами
`STARTUP.WAV` и `SHUTDOWN.WAV`). `disk.img` пересобирается, только если его
удалить — правки внутри него `make run` не трогает.
Мышь захватывается кликом по окну QEMU, освободить: Ctrl+Alt+G.
Если звука не слышно, попробуй `make run AUDIODEV=pa` (PipeWire/PulseAudio
вместо ALSA).
Если OVMF лежит в другом месте: `make run OVMF=/путь/к/OVMF.fd`
(поиск: `find /usr/share -name 'OVMF*.fd'`).

## Управление

- мышь: клик по «Пуск» открывает меню; «Перезагрузка» и «Завершение работы»
  открывают окно «PC Manager» (затемняет всё вокруг); его кнопки Shutdown и
  Reboot по-настоящему выключают/перезагружают QEMU, крестик закрывает окно
- Ctrl+Esc или клавиша Win: меню «Пуск»; Esc закрывает; стрелки вверх/вниз + Enter
- Alt+Shift или Ctrl+Shift: раскладка EN/RU в трее (пока только индикатор)
- клавиши 1..8: тест курсоров

## Шрифт

Terminus уже встроен (`src/font_data.rs` сгенерирован из присланного
`Terminus.ttf`). Чтобы пересобрать с другим TTF:

    sudo apt install imagemagick
    tools/build_font.sh /путь/к/шрифту.ttf > src/font_data.rs

Скрипт рендерит каждый глиф через ImageMagick (без сглаживания, ровно
8x16) и сам ищет нужное окно строки под кириллицу со спускаемыми
элементами (у, р, д, ц, щ) — глифы не обрезаются.

## Известные ограничения шага 5

- AC97: один канал воспроизведения, без записи, без прерываний (опрос).
  `start()` не ждёт — играет в фоне через DMA (для звука при загрузке),
  `play_blocking()` ждёт по-настоящему (для звука при выключении, где экран
  и так статичный). Раньше `start()` был по сути блокирующим — рабочий стол
  замирал на всю длину звука; это исправлено.
- Убрал флаг IOC (запрос прерывания) у дескрипторов — мы прерывания для
  этого устройства не обрабатываем, незачем их и просить.
- Была жалоба на короткий «скачок» звука посреди воспроизведения — глубже
  не разбирал (не на чем проверить), возможно особенность эмуляции AC97 в
  самом QEMU, а не бага в драйвере. Если повторится — опиши точнее момент
  (на какой примерно секунде, всегда ли в одном месте).
- WAV: только 16 бит/стерео/48000 Гц (без расширения VRA у AC97 другой
  частоты и нет). Файлы с другими параметрами тихо отклоняются — конвертировать
  нужно заранее (`ffmpeg -ar 48000 -ac 2 -sample_fmt s16 -c:a pcm_s16le`).
  Присланные `.wav` из SounPack на самом деле оказались MP3 — конвертированы
  так же, лежат в `assets/sounds/`.
- `-device AC97` в QEMU нужен `-audiodev`; см. `AUDIODEV=pa`, если ALSA не видит звук.
- Картинка загрузки — сырой RGB (ширина/высота + байты), без JPEG/PNG-декодера
  в ядре: JPEG превращён в этот формат один раз при подготовке, ядру
  расшифровывать нечего, оно просто копирует байты на экран.

## Известные ограничения шага 4

- Окно «PC Manager» реагирует только на мышь; клавиатура, пока оно открыто,
  ничего не делает (ни Esc, ни Enter его не закрывают).
- «Sleep mode» — заглушка на будущее, специально не нажимается.
- Чёрный экран перед выключением/перезагрузкой ждёт один тик RTC (до
  секунды) — грубо, но сообщение гарантированно успевает быть увидено.

## Известные ограничения шага 2

- IOAPIC берётся по стандартному адресу 0xFEC00000, IRQ = номер входа (верно для QEMU и обычных ПК).
  Разбор ACPI/MADT добавим позже.
- Режим x2APIC не поддерживается (выдаётся синий экран с пояснением).
- Свои таблицы страниц ещё не создаются: используются таблицы Limine. Появятся вместе с процессами (шаг 6).

## Известные ограничения шага 3

- AHCI: один командный слот, без очередей (NCQ), без записи, без прерываний (опрос).
  Хватает для загрузки данных при старте; для настоящей файловой системы под
  нагрузкой этого мало, доработаем при необходимости.
- FAT32: только чтение, только короткие имена 8.3 (VFAT/LFN пока не разбирается).
- Диск без таблицы разделов (FAT32 прямо с LBA 0). MBR/GPT добавим, когда
  понадобится больше одного раздела.
- `ahci::Disk::read` требует буфер из кучи (`Vec`/`Box`), не из стека — иначе
  неверно посчитается физический адрес для DMA. Подробности в начале `ahci.rs`.
